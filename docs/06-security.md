# 06 — Security

## Threat Model

### In scope (เราป้องกัน)
- Unauthorized API access (random external probe)
- Stolen agent token → impersonation
- Replay attacks on scan submission
- Privilege escalation user → admin
- SQL injection / XSS / CSRF
- Secrets leak in logs
- Brute force login

### Out of scope (v1)
- Insider threat (admin abuses access)
- Physical access to endpoint (attacker จะอ่าน agent.token ได้ — ถือว่า game over for that machine)
- Supply chain attack ของ dependency เอง (Go modules / pip / npm)
- Network-level attacks (man-in-the-middle ภายใน LAN — เราใช้ TLS)

## Authentication

### Dashboard users — JWT

- **Algorithm**: HS256 (symmetric, ใช้ secret จาก env)
- **Access token**: 1 hour, stored in memory (React) — ไม่ใช่ localStorage
- **Refresh token**: 30 days, HTTP-only secure cookie, same-site=strict
- **Rotation**: refresh จะ rotate token ทุกครั้ง (one-time use)
- **Logout**: revoke refresh token in DB (table: `revoked_tokens`)

### Agent — Bearer token

- **Format**: 32-byte random, base64url-encoded
- **Storage server**: `machines.agent_token_hash` (bcrypt, cost 12)
- **Storage agent**: file with restrictive ACL
- **Rotation**: admin revoke → token invalid, agent re-enroll
- **Not rotated automatically** ใน v1 (อาจมาใน v2)

### Enrollment token

- One-time, 24h expiry, opaque random string
- Generated by admin in dashboard, displayed once (ไม่เก็บ plaintext ใน DB — เก็บ hash)
- Used by agent ใน enrollment → marked `used_at` → ห้ามใช้ซ้ำ

## Password Policy

- Min length: 12
- ต้องมี: ตัวพิมพ์ใหญ่ + เล็ก + เลข + อักขระพิเศษ
- ห้าม dictionary password (top 10k list) — check ตอน register/change
- Hash: bcrypt cost 12
- Brute force protection: 5 failed attempts / 5 min / IP → lockout 15 min
- Force change ทุก 90 วัน → **NO** (NIST recommendation ตอนนี้ไม่บังคับ rotate)

## Authorization (RBAC)

### Roles
- **admin**: full access ทุก endpoint
- **viewer**: read-only — GET เท่านั้น (ห้าม POST/PATCH/DELETE)

### Implementation
FastAPI dependency:
```python
def require_role(*allowed_roles: str):
    def dep(current_user: User = Depends(get_current_user)) -> User:
        if current_user.role not in allowed_roles:
            raise HTTPException(403, "Insufficient permissions")
        return current_user
    return dep

# Usage
@router.delete("/machines/{uuid}")
async def delete_machine(uuid: UUID, _: User = Depends(require_role("admin"))):
    ...
```

### Agent vs User auth
- Agent token → ใช้กับ `/api/v1/agents/*` เท่านั้น
- User JWT → ใช้กับทุก endpoint **ยกเว้น** `/api/v1/agents/*`
- ห้าม cross-use — middleware check ก่อน handler

## Transport Security

### TLS
- **Production**: TLS 1.3 only, cert จาก Let's Encrypt
- **Development**: self-signed cert via mkcert
- **Agent**: validate cert chain เสมอ. ถ้า user มี internal CA → install ผ่าน OS cert store, ไม่ใช้ `--insecure`

### HSTS
Header: `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`

### CORS
- Backend strict CORS: allow only dashboard origin (จาก env `DASHBOARD_URL`)
- ไม่ใช้ `*` ทุกเมื่อ
- Methods: GET, POST, PATCH, DELETE, OPTIONS

### CSP (Dashboard)
```
default-src 'self';
script-src 'self' 'unsafe-inline';   # next.js requires inline for hydration
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
connect-src 'self' <backend-url>;
frame-ancestors 'none';
```

## Secrets Management

### Storage
- **Production**: env vars from `.env` file (gitignored) + future: Vault / SOPS
- **Development**: `.env.example` checked in, `.env` ignored

### Secrets list

| Secret | Where | Rotation |
|--------|-------|----------|
| `JWT_SECRET` | env | annual or on breach |
| `POSTGRES_PASSWORD` | env | annual |
| `REDIS_PASSWORD` | env | annual |
| `BCRYPT_PEPPER` | env (optional extra) | never (would invalidate all passwords) |
| `LICENSE_KEY_ENCRYPTION_KEY` | env, AES-256 | annual |
| Agent tokens | DB (hashed) | per-machine on revoke |

### Logging
- **NEVER** log: passwords, tokens (full), JWT, license_key, request body containing credentials
- ทุก secret column ใน SQLAlchemy model mark ด้วย `repr=False`
- Pydantic schema ที่มี secret ใช้ `SecretStr` หรือ exclude ใน `model_dump()`

## Input Validation

### SQL injection
- ใช้ SQLAlchemy ORM/Core เท่านั้น — ห้าม f-string ลง raw SQL
- ถ้า raw SQL จำเป็น → `text("...")` + parameterized

### XSS
- Next.js auto-escape JSX
- ห้าม `dangerouslySetInnerHTML` (มี exception ต้อง review)
- Markdown render (ถ้ามี) ใช้ `react-markdown` + sanitize plugin

### File upload (Whitelist CSV bulk import)
- Max size: 5 MB
- Accept: `text/csv` only
- Parse: `csv.DictReader` with strict column whitelist
- ไม่ store file — parse แล้วทิ้ง

---

## CSRF

- Refresh token ใน HTTP-only cookie → vulnerable to CSRF
- Mitigation: `SameSite=Strict` + double-submit pattern (CSRF token in header + cookie, must match)
- Access token ใน `Authorization` header → not CSRF-able

---

## Rate Limiting

ใช้ Redis-based limiter (`slowapi` หรือ custom)

| Endpoint | Limit |
|----------|-------|
| `POST /auth/login` | 5 / 5 min / IP |
| `POST /agents/enroll` | 10 / hr / IP |
| `POST /agents/heartbeat` | 120 / min / token (2x normal rate) |
| `POST /agents/scans` | 6 / hr / token |
| Other authenticated | 1000 / min / user |
| Unauthenticated | 60 / min / IP |

Return `429` + `Retry-After` header

## Encryption at Rest

### License keys
ใน `licenses.license_key` column — encrypted ด้วย AES-256-GCM, key จาก env (`LICENSE_KEY_ENCRYPTION_KEY`)
- Implementation: `cryptography` library, `Fernet` (built-in AES + HMAC)
- Application-level encryption — DB เก็บ ciphertext

### Database backup
- Outside scope ของ application — ใช้ Postgres `pg_dump` + GPG encrypt → S3 (admin responsibility)

- License CRUD
- Machine delete / scan trigger

## Compliance Considerations

- **PDPA (Thailand)**: agent ห้ามเก็บ PII. Software inventory ไม่ใช่ PII โดยปกติ
- **GDPR**: ถ้า deploy ใน EU → user data ใน `users` table = email + name → ต้องมี DPA + delete endpoint
- **SOC 2** (future): ทุก mutation มี audit log + admin access ผ่าน RBAC = compliant by design

## Incident Response (informal v1)

1. Detect: admin เจอ alert / log ผิดปกติ
2. Contain: revoke compromised tokens (`UPDATE machines SET agent_token_hash = NULL WHERE ...`)
3. Investigate: query audit_logs
4. Eradicate: patch + rotate secrets
5. Recover: re-enroll affected agents
6. Lessons learned: doc ใน `docs/incidents/`
