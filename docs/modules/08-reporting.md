## Features & Acceptance Criteria

### 8.1 PDF org summary report
**Sections:**
1. Cover: org name, report date, generated by user
2. Executive summary: machines count, vulnerabilities critical/high, compliance rate, top risks
3. Fleet overview: bar chart machines by OS, line chart vuln trend
4. Top 10 risky machines: table
5. Top 10 vulnerabilities (by affected count): table with CVE detail
6. License compliance: status breakdown + over-used list
7. Unauthorized software: list of alerts + machines
8. Appendix: methodology, generation timestamp

**Tech:** `weasyprint` (HTML/CSS → PDF)

**Template:** `backend/app/reports/templates/org_summary.html` + `org_summary.css`
- Use brand color from `policy_settings.brand_color` (default: corporate blue)
- Logo upload (settings page) → embed in cover

**Acceptance:**
- Generate ≤ 10s for fleet 1000 machines
- All sections render (no missing data shown as "—")
- Page numbers + table of contents
- Print-friendly (A4 portrait)

### 8.2 PDF per-machine report
**Sections:**
1. Cover: hostname, report date
2. Machine info: OS, last scan, tags, agent version
3. Risk score breakdown
4. Software inventory (full table — collapsible by category)
5. Vulnerabilities (with CVE detail + recommended versions)
6. Signature status
7. Recent history (install/uninstall events last 30 days)
8. Alerts (open + recent resolved)

**Tech:** weasyprint, same as 8.1

**Acceptance:**
- Generate ≤ 5s per machine
- All sections present, hide empty sections (e.g. "No vulnerabilities" section if 0)

### 8.3 CSV exports
**Tables to export:**
- Machines list (with filters preserved)
- Software inventory (per-machine or cross-machine)
- Vulnerabilities
- Licenses
- Alerts (open or all)
- Audit log

**UI:** "Export CSV" button on each list page → uses current filters/search

**Format:** UTF-8 with BOM (for Excel compatibility), `,` separator, RFC 4180 quoting

**Acceptance:**
- Export Excel opens correctly with Thai characters
- Filtered list exports only those rows
- Large export (50k rows): streaming response, no OOM

### 8.4 Async report generation
**Flow:**
1. `POST /api/v1/reports/generate {type, params, format}` → return `report_uuid`
2. Backend enqueue arq job
3. Worker generates PDF/CSV → store ใน `reports/` filesystem (or S3)
4. Update `reports` table: status `completed`, file_path, file_size
5. Client poll `GET /api/v1/reports/{uuid}` → see status
6. When ready, download via `GET /api/v1/reports/{uuid}/download`

**Storage:**
- Local filesystem: `/app/reports/{uuid}.pdf` (mount as volume)
- Retention: 30 days, daily cleanup job

**Acceptance:**
- Click "Generate report" → toast "Report queued" → poll shows progress
- When ready → "Download" button enabled
- Refresh page → still see report list (persistent)

### 8.5 Scheduled reports
**UI:** `/reports/schedules`

**Schedule fields:**
- name (e.g. "Weekly Org Summary")
- report_type (org_summary / machine_detail)
- target_machine_uuid (if machine_detail)
- format (pdf / csv)
- cron expression (e.g. `0 9 * * MON` = every Monday 9am)
- recipients: email list (Phase 5 deliver) — v1 store path

**Worker:** cron-driven, generate + email (Phase 5) หรือ save to filesystem

**Acceptance:**
- Create schedule "Every Monday 9 AM" → next monday 9am → report generated
- Disable schedule → stop firing
- Delete schedule → also delete future runs

### 8.6 Report list page
**UI:** `/reports`

**Table:**
- Name (with type icon)
- Generated by user
- Generated at
- Format
- File size
- Status (queued / running / completed / failed)
- Actions: download, delete (admin)

**Acceptance:**
- Show latest 100 reports
- Filter by type, date range
- Click row → download (if completed)

## API endpoints

```
POST   /api/v1/reports/generate
       body: {type: 'org_summary'|'machine_detail', machine_uuid?, format: 'pdf'|'csv', params?}
       returns: {report_uuid, status: 'queued'}

GET    /api/v1/reports
GET    /api/v1/reports/{uuid}
GET    /api/v1/reports/{uuid}/download        # binary, content-disposition attachment
DELETE /api/v1/reports/{uuid}

GET    /api/v1/reports/schedules
POST   /api/v1/reports/schedules
PATCH  /api/v1/reports/schedules/{uuid}
DELETE /api/v1/reports/schedules/{uuid}
POST   /api/v1/reports/schedules/{uuid}/run-now    # manual trigger

# Inline CSV exports (synchronous for small data, async for large)
GET    /api/v1/machines/export?format=csv...
GET    /api/v1/software/export?format=csv...
GET    /api/v1/vulnerabilities/export?format=csv...
GET    /api/v1/licenses/export?format=csv...
GET    /api/v1/alerts/export?format=csv...
GET    /api/v1/audit-logs/export?format=csv...
```

## Edge cases

1. **Empty report data** (machine has 0 software): generate ยังได้, sections show "—" or "No data"
2. **Huge fleet (5000+ machines org_summary)**: split appendix tables to "Top N" + reference "See dashboard for full list"
3. **Concurrent generates**: arq job dedupe? — same params + within 1 min → return existing report_uuid (idempotency)
4. **Report file disk full**: detect + error, alert admin
5. **Cron firing while previous run still in progress**: skip (idempotent), log warning
6. **Time zone**: cron interpret in server TZ. Store + display TZ explicitly in schedule UI
7. **CSV ที่มี comma ในชื่อ software**: RFC 4180 quote — `"My, Cool Software"`
